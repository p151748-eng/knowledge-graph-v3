# KG-Agent 操作演示

本文提供几组适合录屏、截图或 README 展示的端到端演示脚本。每个 Demo 都包含用户输入、建议路径和预期观察点。

## Demo 1：研究空白分析 + 最新论文联网补充

### 目标

验证系统能在研究选题场景中保留上下文主题，并在第二轮联网搜索时优先补充真实论文、引用标记和引用链接。

### 操作步骤

1. 打开前端聊天页：

```text
http://localhost:5173
```

2. 第一轮输入：

```text
我想研究“多智能体 RAG 在医学论文阅读中的应用”，帮我分析这个选题的研究空白和创新点。
```

3. 观察结果：

- 路径通常为 `paper_assistant` 或 `research`。
- 回答应包含研究背景、已有工作、研究空白、创新点和可验证方向。
- 如果本地证据不足，系统可能提示需要联网补充。

4. 第二轮输入：

```text
帮我联网搜索这个选题的相关论文，重点找 2024 年以后的最新研究。
```

5. 观察结果：

- 系统应将“这个选题”解析为上一轮的“多智能体 RAG 在医学论文阅读中的应用”。
- 学术搜索优先返回真实论文。
- 正文关键结论后应出现 `[1]`、`[2]` 等引用标记。
- 回答末尾应包含“参考论文”“引用来源”或“引用链接”。
- 来源字段应尽量包含标题、作者、年份、URL、provider。

### 可选 API 调用

```bash
curl -X POST http://localhost:8001/api/chat/paper \
  -H "Content-Type: application/json" \
  -d '{"message":"我想研究多智能体 RAG 在医学论文阅读中的应用，帮我分析这个选题的研究空白和创新点。"}'
```

如果需要保持两轮上下文，请使用第一轮返回的 `conversation_id` 继续调用。

## Demo 2：arXiv 论文导入 + Paper Assistant 问答

### 目标

验证论文导入、分片、图谱抽取和论文助手问答链路。

### 操作步骤

1. 打开“知识导入”页面。
2. 选择 arXiv 导入。
3. 输入一篇论文的 arXiv ID 或 URL。
4. 等待导入完成。
5. 打开“文档库”，确认论文已经出现在列表中。
6. 回到“聊天”页面，输入：

```text
请概括这篇论文的研究问题、核心方法、实验设计和主要贡献。
```

7. 继续输入：

```text
请解释这篇论文的方法部分，并指出它相对传统 RAG 的创新点。
```

### 预期观察点

- 文档库出现新文档。
- 论文助手回答引用本地论文片段或章节信息。
- 来源面板显示文档 chunk、章节或分片信息。
- 复杂论文问题会比普通 FastPath 更结构化。

### 可选 API 调用

```bash
curl -X POST http://localhost:8001/api/ingest/arxiv \
  -H "Content-Type: application/json" \
  -d '{"arxiv_id_or_url":"https://arxiv.org/abs/2401.00001", "prefer_html":true}'
```

## Demo 3：Self-RAG 可靠性验证

### 目标

展示系统在证据不足或需要验证时，如何进行检索评分、检索修复和联网验证。

### 操作步骤

在聊天页输入：

```text
请验证 Self-RAG 机制在论文问答中是否可靠，并补充论文和官网依据。
```

### 预期观察点

- 路径应进入 `self_rag` 或研究型验证流程。
- 执行步骤中出现证据评分、检索修复或联网验证相关阶段。
- 如果问题同时要求“论文”和“官网依据”，系统应混合使用学术搜索和 Web Search。
- 回答应说明哪些结论有证据支持，哪些仍存在不确定性。

### 可选 API 调用

```bash
curl -X POST http://localhost:8001/api/chat/self-rag \
  -H "Content-Type: application/json" \
  -d '{"message":"请验证 Self-RAG 机制在论文问答中是否可靠，并补充论文和官网依据。"}'
```

## Demo 4：知识图谱搜索与可视化

### 目标

展示文档导入后，系统如何把实体和关系沉淀到知识图谱，并支持可视化探索。

### 操作步骤

1. 先导入一篇论文或一段技术文档。
2. 打开“知识图谱”页面。
3. 在搜索框输入：

```text
RAG
```

或输入某个论文方法名、数据集名、指标名。

4. 点击搜索。
5. 切换到图谱视图。
6. 观察节点、边和关系标签。

### 预期观察点

- 搜索结果返回实体和相关关系。
- 图谱视图展示节点连边。
- 可以选择中心节点查看局部网络。
- 可以手动新增、编辑或删除节点和边。

### 可选 API 调用

```bash
curl "http://localhost:8001/api/kg/search?q=RAG&mode=hybrid&top_k=10"
```

```bash
curl "http://localhost:8001/api/kg/graph?depth=1&limit=150"
```

## Demo 5：路径选择与路由可观测性

### 目标

展示同一个聊天入口如何根据问题类型选择不同工作流。

### 示例输入

简单定义：

```text
什么是 RAG？
```

复杂分析：

```text
RAG 和知识图谱结合时，各自解决了什么问题？有什么局限？
```

论文助手：

```text
帮我分析这篇论文的方法创新和实验设计。
```

研究规划：

```text
我想做一个面向医学论文阅读的 Agentic RAG 系统，请帮我设计研究方案和评估指标。
```

时效验证：

```text
请联网验证最近是否有 Agentic RAG 在医学场景中的新论文。
```

### 预期观察点

- 简单定义倾向 `fast`。
- 复杂分析倾向 `pipeline`。
- 论文问题倾向 `paper_assistant`。
- 研究方案倾向 `research`。
- 最新/验证类问题倾向 `self_rag` 或联网补充。
