# KG-Agent：面向论文阅读与研究选题的智能研究工作台

KG-Agent 是一个面向学习者、研究者和开发者的个人研究工作台。它把论文阅读、知识库问答、研究选题、证据验证和知识图谱整理放在同一个界面里，让你可以围绕自己的资料持续提问、分析和沉淀。

它适合这样的使用方式：先把论文、笔记或技术文档导入系统，再像和研究助理对话一样，询问论文内容、比较方法差异、寻找研究空白、生成技术路线，并检查每个结论背后的证据来源。

## 你可以用它完成什么

KG-Agent 不是只回答“文档里有什么”。它更关注研究过程中经常遇到的几个实际问题：

| 你想做的事 | KG-Agent 可以怎么帮你 |
| --- | --- |
| 快速理解概念 | 用简洁方式解释 RAG、Self-RAG、GraphRAG 等概念。 |
| 阅读一篇论文 | 总结论文的问题、方法、实验、贡献和局限。 |
| 比较多种方法 | 对比不同方法的机制、适用场景和研究价值。 |
| 找研究空白 | 结合本地资料和外部论文，分析哪些方向还值得做。 |
| 设计开题方案 | 把研究方向整理成研究问题、技术路线、实验设计和风险。 |
| 验证一个结论 | 检查回答是否有证据支撑，必要时联网补充资料。 |
| 整理长期知识库 | 把论文、概念、方法和关系沉淀到知识图谱里。 |

## 场景一：刚开始读一篇论文，不知道重点在哪里

很多时候，打开一篇论文后最难的是快速判断：它到底解决了什么问题？方法新在哪里？实验是否有说服力？适不适合放进自己的相关工作？

在 KG-Agent 中，你可以先导入论文，然后直接问：

```text
请概括这篇论文的研究问题、核心方法、实验设计和主要贡献。
```

继续追问：

```text
这篇论文的方法部分有什么创新？和传统 RAG 有什么区别？
```

系统会把问题交给论文助手处理。它会优先查找本地论文分片，而不是凭空生成一段通用总结。你可以看到回答引用了哪些片段，也可以继续围绕方法、实验、局限和写作角度追问。

这个场景适合：

- 第一次快速浏览论文。
- 准备组会汇报。
- 整理论文阅读笔记。
- 判断一篇论文是否值得深入读。
- 提取可放入相关工作的内容。

## 场景二：已经有一个研究方向，但不知道是否值得做

研究选题通常不会一开始就很清晰。你可能只有一个大概想法，例如“多智能体 RAG”“医学论文阅读”“个人知识库助手”，但还不知道它的研究空白在哪里。

你可以这样问：

```text
Agentic RAG 在 2026 年还有哪些最新研究空白？请基于证据给出一个可做的研究问题。
```

KG-Agent 会把它识别为研究空白分析任务，然后按步骤执行：

1. 判断这是研究型问题，而不是普通问答。
2. 先查本地知识库中是否有相关论文和资料。
3. 如果本地证据不足，触发学术联网检索。
4. 根据证据整理研究空白。
5. 生成一个可以继续展开的研究问题。
6. 检查最终回答是否被证据支撑。

在一次真实测试中，本地证据被人为置空后，系统自动进行了联网补证，并返回了两条 2026 年相关学术结果。其中一条论文指出，Agentic RAG 在面对超出知识库范围的问题时，仍缺少系统的查询建议机制。系统据此把研究问题收敛为：

```text
如何在 Agentic RAG 系统中设计一个动态查询建议与引导机制，当用户问题超出知识库范围时，主动生成语义相似、可回答的替代查询，从而避免幻觉并维持有效交互？
```

这个场景适合：

- 论文选题初筛。
- 找本科 / 硕士论文切入点。
- 从一个大方向收敛到具体研究问题。
- 判断某个方向是否有足够文献支撑。
- 为开题报告准备“研究意义”和“创新点”。

## 场景三：比较多个方法，找出适合自己项目的技术路线

在做 RAG 或 Agent 项目时，经常会遇到多个相似方法：Self-RAG、CRAG、GraphRAG、Agentic RAG、Hybrid RAG……它们看起来都相关，但适用场景并不一样。

你可以问：

```text
比较 Self-RAG、CRAG、GraphRAG 的差异，并给出个人知识库研究助手的研究切入点。
```

系统会尝试从本地论文和知识库中查找证据。如果某个方法证据不足，它不会强行编出完整对比，而是会明确说明哪些部分有依据、哪些部分还需要补充论文。

例如，当本地只有 Self-RAG 相关证据，而 CRAG 和 GraphRAG 证据不足时，系统会优先展开 Self-RAG 的机制，并提示另外两个方法需要补充论文后再做严谨比较。

这个场景适合：

- 技术路线选型。
- 研究方案设计。
- 写论文相关工作对比。
- 判断某个方法是否适合自己的系统。
- 从已有方法中组合出新的研究思路。

## 场景四：你不只想要答案，还想知道答案靠不靠谱

对于研究类问题，只得到一段流畅回答是不够的。你还需要知道：这个结论有没有证据？证据来自本地还是联网？是论文还是网页？有没有部分结论没有支撑？

KG-Agent 会把证据作为一等信息展示出来。

<p align="center">
  <img src="assets/demo-evidence-panel.svg" alt="Evidence Panel" width="100%" />
</p>

在证据面板中，你可以看到：

- 证据标题
- 作者和年份
- 来源平台
- URL
- 摘要片段
- 来自本地、论文库、图谱还是联网
- 当前证据对回答的支撑状态

如果回答只有部分证据支撑，系统会显示为“部分支撑”或“需要补证”，而不是把所有内容都包装成确定结论。

这个场景适合：

- 检查 AI 回答是否可靠。
- 准备论文写作前确认引用依据。
- 区分“有证据的结论”和“模型推测”。
- 避免把未经支撑的内容写进报告或论文。

## 场景五：需要验证一个结论，而不是重新写一篇回答

有时你已经有一个判断，只想知道它是否成立。例如：

```text
这个结论可靠吗？请基于论文和官网依据验证。
```

这类问题会更适合进入 Self-RAG / CRAG 类流程。系统会先检查本地证据是否足够，如果不足，再决定是否修复检索或联网补证。

它关注的不是“写得更完整”，而是：

- 当前证据是否相关？
- 支撑力度够不够？
- 是否需要换 query 再查一次？
- 是否需要联网找外部依据？
- 最终结论应该是支持、部分支持，还是证据不足？

这个场景适合：

- 检查论文笔记中的结论。
- 验证一段综述文字是否站得住。
- 在写报告前确认事实依据。
- 对模型回答做二次审查。

## 场景六：把论文和笔记变成长期可用的知识图谱

KG-Agent 不只是把文档切成向量分片。它还可以把论文、概念、方法、实验、数据集和指标沉淀成知识图谱。

当你导入多篇论文后，可以在知识图谱页面搜索：

```text
Self-RAG
```

你可以观察它关联了哪些概念、方法、任务或评价指标，也可以查看某篇论文和其他论文之间的关系。

这个场景适合：

- 构建自己的论文知识库。
- 观察一个研究方向中的概念关系。
- 管理长期学习笔记。
- 找到不同论文之间的连接点。
- 为后续研究和写作提供结构化素材。

## 一个完整的研究使用流程

你可以把 KG-Agent 当作一个从阅读到研究的连续工作台：

```text
导入论文 / 笔记
  ↓
让论文助手总结论文方法和贡献
  ↓
把关键概念和关系沉淀到知识图谱
  ↓
围绕研究方向提出问题
  ↓
让研究助手比较方法、寻找空白、设计路线
  ↓
用 Self-RAG 检查关键结论是否有证据
  ↓
根据证据面板确认哪些内容可以写进报告或论文
```

这个流程特别适合做课程项目、毕业设计、开题准备、论文综述和个人知识库建设。

## 不同模式该怎么选

| 如果你想…… | 建议选择 |
| --- | --- |
| 问一个定义或简单概念 | 快速回答 |
| 基于知识库问概念关系 | 标准流程 |
| 阅读或分析单篇论文 | 论文助手 |
| 检查一个结论是否可靠 | Self-RAG |
| 做综述、选题、研究空白、技术路线 | 研究助手 |
| 不确定该选哪个 | 自动选择 |

前端顶部可以手动切换模式，每个模式都会显示适合的使用范围。你也可以选择自动模式，让系统根据问题判断。

## 和普通 RAG 工具有什么不同

普通 RAG 工具通常解决的是“从文档中找答案”。KG-Agent 更关注研究场景下的完整链路。

| 普通 RAG 工具 | KG-Agent |
| --- | --- |
| 一个问答流程处理所有问题 | 根据问题类型选择不同工作流 |
| 主要回答文档内容 | 同时支持论文阅读、研究选题、证据验证和图谱沉淀 |
| 来源展示较简单 | 展示原始证据、来源、摘要、支撑状态和验证结果 |
| 证据不足时可能继续生成 | 可以提示证据不足、联网补证或进行检索修复 |
| 多轮研究容易丢上下文 | 能理解“这个选题”“继续刚才”等追问 |
| 文档多为向量分片 | 同时维护文档库、向量检索和知识图谱 |
